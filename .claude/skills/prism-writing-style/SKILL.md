# PRISM-HU 表記ルール

prism-hu.org（公開サイト）と support.prism-hu.org（学内限定）で共通。姉妹 repo にも同じファイルを置く。

## 優先順位

1. **このサイトの決め事**（下の表）。固有名詞・専門用語・英語・人名の書き方。
2. **共同通信社『記者ハンドブック』**（最新版）。常用漢字の範囲、送り仮名、かな書き、数字と記号。迷ったらこれに従う。
3. 上のどちらにも無いものは、サイト内の既存の書き方に揃える（`grep` で先例を探す）。

北大広報課の「和文プレスリリース 記載ルール」は採用しない（漢字寄りの古い表記で、記者ハンドブックと逆のため。2026-10-16 事務局決定）。

## 機械チェック

- `prh.yml`（リポジトリ直下）が機械で判定できる分の正本。`pnpm lint:text` で `src/content/**/*.md` を検査、`pnpm lint:text:fix` で直せるものは自動で直す。
- CI は PR ごとに `pnpm lint:text` を回す。赤なら PR はマージしない。
- 記事を書いたら、必ず `pnpm lint:text` を通してから PR を出す。
- `prh.yml` のルールに当てはめたくない箇所（引用、固有名詞、原文どおりに残す業績名など）は、その行の前後を `<!-- textlint-disable -->` と `<!-- textlint-enable -->` で囲む。
- 研究成果（`src/content/publications/*.yaml`）は原文どおりが原則なので検査対象外。
- **機械チェックが届かない所**: frontmatter（`title:` `description:` など）と、本文に直接書いた HTML（`<p class="news-foot">` など）の中は textlint が見ない。ここは目で確認する（リンクの文字・強調・引用・見出しは検査対象）。

## 書くときの手順

1. 既存の似た記事を 1 本開いて、frontmatter と見出しの型を合わせる（README「記事の書き方」）。
2. 本文を書く。固有名詞は上の表、迷う語は記者ハンドブック。
3. `pnpm lint:text` → 赤が出たら直す（`pnpm lint:text:fix` で直せるものは自動）。
4. `pnpm check` と `pnpm build` を通し、`pnpm dev` で日英両方を目で見る。
5. PR の説明に「表記チェック済み」と書く。

## ルールを増やすとき

- 揺れを見つけたら、決め事をこの表に足し、機械で判定できるなら `prh.yml` にも足す（`expected` が正、`pattern` が誤り）。
- `prh.yml` を直したら `pnpm lint:text` を全体に回して誤検出が無いか見る。人名の規則は誤検出しやすいので、追加後に `git diff` で直った箇所を全部読む。
- 両方の repo（website / support）に同じ変更を入れる。
